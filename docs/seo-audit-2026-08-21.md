# SEO Audit — jtbuildsco.com

**Date:** 21 August 2026
**Scope:** 8 indexable pages, live site (both hosts) + repo source
**Totals:** 2 critical · 5 high · 6 medium · 11 passing

Summary: the build is clean — fast, semantic, accessible, correctly cached. What holds it
back is a host mismatch that makes every canonical signal contradict the server, and a
footprint too small to compete for the searches that bring in salon and trades work.

---

## Critical

### 01 — Every canonical URL points at a host that 308-redirects

`jtbuildsco.com` issues a 308 to `www.jtbuildsco.com` for every path. But all 8
`<link rel="canonical">` tags, all 8 `og:url` values, all 8 `<loc>` entries in
`sitemap.xml`, the `Sitemap:` line in `robots.txt`, and the `url` / `logo` / `image`
fields in the homepage JSON-LD declare the bare apex.

```
$ curl -I https://jtbuildsco.com/
HTTP/2 308
location: https://www.jtbuildsco.com/

$ curl -o /dev/null -w '%{http_code}' https://jtbuildsco.com/sitemap.xml
308        # all 8 sitemap URLs behave the same way
```

Google is following the chain and indexing `www`, so the damage today is dilution, not
exclusion — but crawl budget is spent on redirects, the signals contradict each other,
and any backlink to the apex passes through a hop.

**Fix:** standardise on `https://www.jtbuildsco.com` (what is live and indexed). One
find-and-replace of `https://jtbuildsco.com` → `https://www.jtbuildsco.com` across the
repo covers canonicals, `og:url`, sitemap, robots and JSON-LD. Or flip the Vercel
redirect so the apex is primary — but make the whole site agree.

### 02 — The Google verification file only resolves through a redirect

```
$ curl -o /dev/null -w '%{http_code}' https://jtbuildsco.com/googlec74958a3d936dbae.html
308
$ curl -o /dev/null -w '%{http_code}' https://www.jtbuildsco.com/googlec74958a3d936dbae.html
200
```

If the Search Console property is the apex URL-prefix, reporting is also on the wrong
host — impressions and clicks land on `www`.

**Fix:** add a **Domain property** (DNS TXT). Covers apex, `www`, http, https and every
subdomain including `report.jtbuildsco.com`, and can't be broken by a redirect rule.
Resubmit `https://www.jtbuildsco.com/sitemap.xml` against it.

## High priority

### 03 — `/pricing` has 13 FAQ entries and no `FAQPage` markup

Thirteen `<details>`/`<summary>` Q&A pairs covering timeline, domains, ownership, SEO
scope, carrier registration and service area. 923 words — the deepest page on the site,
already semantic and crawlable, with zero structured data on it.

**Fix:** add `FAQPage` JSON-LD with all 13 `Question` / `acceptedAnswer` pairs mirroring
the visible text. "What does the 48-hour timeline actually mean?", "Is SEO included?"
and "Do I own my website?" are strong AI-answer citation candidates.

### 04 — Structured data stops at the homepage

```
index.html          1   ProfessionalService + OfferCatalog
services.html       0
pricing.html        0
work.html           0
about.html          0
contact.html        0
```

**Fix:** `Service` entities on `/services` (one per offering, with `provider`,
`serviceType`, `areaServed`); `BreadcrumbList` on every non-home page; a site-wide
`WebSite` + `Organization` pair; `ItemList` of `CreativeWork` on `/work`.

### 05 — No phone number anywhere, and thin local business data

The only phone-shaped string in the repo is the `(555) 555-5555` placeholder in a
dashboard form field. The `ProfessionalService` schema has locality/region/country but
no `telephone`, `streetAddress`, `postalCode`, `geo` or `openingHoursSpecification`.
`sameAs` lists Instagram and LinkedIn but no Google Business Profile.

For a business selling "Google Business Profile setup" and "Local Search", incomplete
NAP data is both a ranking and a credibility problem.

**Fix:** publish a real phone number in the footer and on `/contact`, marked up in
schema. Add `postalCode: "02035"`, `geo`, hours. Claim the GBP as a service-area
business and add its URL to `sameAs`.

### 06 — Zero location pages, which is how the competition is winning

Competitors ranking for "web design Foxboro MA" all hold dedicated town pages:

- Hup Creative — `/towns/web-design-in-foxborough,-ma`
- WRIS — `/website-design-services/ma/foxboro`
- JF Designs — `/united-states/ma/foxborough/`
- inConcert — `/web-design-and-development-for/Foxborough/Massachusetts/`

You have six commercial pages, none targeting a town. Note also that the town is spelled
both *Foxboro* and *Foxborough* in the wild; the site only ever uses the former.

**Fix:** build one substantial Foxboro page with real local proof, then extend to
surrounding towns. Cover both spellings naturally. Cross-link from the footer, give each
its own `LocalBusiness` + `areaServed` schema.

### 07 — 3,124 words site-wide, and nothing that could earn a link

```
/pricing         923      <- deepest, and it's the FAQ doing the work
/                840
/about           420
/services        410
/work            368
/contact         163
                -----
                3,124
```

The copy that exists is well written and distinctive — that's the hard part. There just
isn't enough of it, and none targets informational queries. The Website Health Report at
`report.jtbuildsco.com` is the most linkable asset here and has no SEO scaffolding
(finding 11).

**Fix:** a modest content layer aimed at pre-purchase questions — what a small business
website should cost, whether a Facebook page is enough, how to claim a GBP. Two or three
genuinely useful pieces beat a posting schedule. Point outreach at the free tool.

## Medium priority

### 08 — Two meta descriptions overrun

```
page              title    description
/                  58 ch    200 ch   <- cut at ~160
/services          61 ch    201 ch   <- cut at ~160
/contact           33 ch    187 ch   <- borderline
/about             50 ch    182 ch   <- borderline
/pricing           25 ch    156 ch
/work              31 ch    161 ch
```

On the homepage the truncated clause is "serving all fifty states" — a real
differentiator. Titles are all well within limits.

**Fix:** trim `/` and `/services` to 150–160 chars, front-loading location and offer.

### 09 — No custom 404

A missing URL returns Vercel's default: 79 bytes of `text/plain`. Status code is correct
(no indexing harm), but visitors hit a dead end with no nav and no branding.

**Fix:** add `404.html` using the existing shell, with nav and links to `/work` and `/contact`.

### 10 — The favicon is heavier than the stylesheet

```
/css/style.css           7.9 KB   brotli
/js/reveal.js            0.7 KB   brotli
/assets/logo-icon.png    4.1 KB
/assets/favicon.png     43.3 KB   256x256 PNG, requested on every page
/assets/og-image.png    47.0 KB   1200x630, correct
```

No `apple-touch-icon` either, so iOS home-screen saves fall back to a screenshot.

**Fix:** export a 32×32 favicon (<2 KB) and add a 180×180 `apple-touch-icon`.

### 11 — The report subdomain has no SEO scaffolding

`report.jtbuildsco.com` serves a real page with a good title and description and is
linked from every footer, but has **no `robots.txt`** (404), **no canonical**, and **no
sitemap**.

**Fix:** decide whether the tool should rank. If yes: robots + self-referencing canonical
+ sitemap, and include the subdomain in the Domain property from finding 02. If no:
`noindex` it and put a tool landing page on the main site.

### 12 — Sitemap has no `lastmod`

All 8 entries use `<changefreq>` and `<priority>`, both of which Google disregards. None
carries `<lastmod>`, the one field Google does use for recrawl scheduling.

**Fix:** add `<lastmod>` per URL (ideally generated from git commit dates at build time)
and drop the other two fields.

### 13 — Open Graph image lacks dimension and alt hints

`og:image` is correctly 1200×630 and every page has a complete card, but
`og:image:width`, `og:image:height` and `og:image:alt` are absent — some platforms render
a small card on first share while they fetch the image. No `theme-color` meta either.

**Fix:** add the three `og:image:*` tags and a `theme-color` to all 8 pages.

## Already right (verified, no action needed)

- One `h1` per page, clean h1→h2→h3 hierarchy with no skipped levels on all 8 pages.
- Every image has an `alt`; decorative logos correctly use empty alt; work screenshots
  have genuinely descriptive text.
- All 33 `<img>` tags carry explicit `width` and `height` — no layout shift.
- The three below-fold work screenshots use `loading="lazy"`; above-fold logos don't.
- Brotli compression (`content-encoding: br`) with `x-vercel-cache: HIT`.
- Median TTFB 0.24 s across 8 pages; heaviest page is 17 KB of HTML.
- HSTS with 2-year max-age (`max-age=63072000`).
- `cleanUrls` with correct 308s (`/about.html` → `/about`) — no duplicate-content split.
- `/dashboard` excluded twice: `X-Robots-Tag: noindex` plus a `robots.txt` disallow.
- FAQ content is native `<details>` HTML, not JavaScript-injected.
- Fonts don't block render: `preconnect` to both hosts plus `&display=swap`.
